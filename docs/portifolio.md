
# Raul Ferraz — Portfólio

## 1. Objetivo

Criar um portfólio pessoal, moderno e interativo que funcione como uma vitrine profissional dos conhecimentos, projetos e experiências de Raul Ferraz.

O site deve atender a dois públicos:
- Pessoas interessadas em conhecer ou contratar meus serviços como desenvolvedor freelance.
- Recrutadores e profissionais de tecnologia interessados em avaliar meus conhecimentos.

O foco é apresentar meu trabalho, não criar um site comercial de vendas.

## 2. Sobre mim

Nome: Raul Ferraz

Formação: Estudante de Ciência da Computação na CESAR School, atualmente no 5º período.

Interesses: Desenvolvimento de software, backend, aplicações web, bancos de dados e resolução de problemas.

As descrições pessoais devem ser profissionais, naturais e sem informações inventadas.

## 3. Navegação principal

O site terá duas áreas principais:

### Home — "/"

Página pessoal com rolagem vertical e as seguintes seções:

1. Hero
   - Nome e apresentação.
   - Personagem GLB interativo com fallback estático, conforme solicitação de 06/11/2026.
   - Botão para explorar os projetos.
   - Barra de navegação flutuante.

2. Sobre mim
   - Formação, interesses e objetivos.
   - Uma apresentação mais humana da minha trajetória.

3. Projetos em destaque
   - Prévia dos principais projetos.
   - Link para a galeria completa.

4. Tecnologias e habilidades
   - Linguagens de programação.
   - Frameworks.
   - Bancos de dados.
   - Ferramentas e metodologias.
   - Relação entre tecnologias e projetos.

5. Experiências e formação
   - Graduação.
   - Experiências práticas.
   - Projetos acadêmicos.
   - Certificações, quando existirem.

6. Minha trajetória
   - Linha do tempo da evolução técnica.
   - Aprendizados importantes.

7. Contato
   - GitHub.
   - LinkedIn.
   - E-mail profissional.
   - Possibilidade de baixar o currículo.

### Projetos — "/projetos"

Galeria visual com:
- Cards de projetos.
- Imagens e prévias.
- Filtros por tecnologia e área.
- Animações discretas ao interagir.
- Navegação para os detalhes de cada projeto.

### Detalhes — "/projetos/:slug"

Cada projeto terá uma página individual com:

1. Nome e descrição.
2. Problema ou objetivo.
3. Solução implementada.
4. Funcionalidades.
5. Demonstração visual.
6. Tecnologias utilizadas.
7. Arquitetura e decisões técnicas.
8. Desafios e aprendizados.
9. Links para GitHub e demonstração, quando disponíveis.

## 4. Conteúdo dos projetos

Os projetos devem ser armazenados em uma estrutura de dados reutilizável.

Não inventar funcionalidades, resultados ou tecnologias utilizadas.

Projetos acadêmicos e pessoais podem ser incluídos, desde que sua natureza seja identificada corretamente.

## 5. Funcionalidades gerais

- Navegação responsiva.
- Transições suaves.
- Links funcionais.
- Filtros de projetos.
- Integração com GitHub por links.
- Páginas individuais dos projetos.
- Acessibilidade básica.
- Suporte a usuários que preferem menos animação.

## 6. Restrições

Não incluir:
- Formulários de orçamento.
- Tabelas de preços.
- Depoimentos fictícios.
- Experiências profissionais inventadas.
- Funcionalidades sem utilidade real.

## 7. Prioridades

1. Qualidade visual.
2. Clareza na apresentação.
3. Boa experiência de navegação.
4. Organização do código.
5. Responsividade.
6. Desempenho e acessibilidade.
